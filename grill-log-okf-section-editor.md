## Q2: Visual Form & YAML Editor Synchronization

**Q:** How should the dynamic Schema-driven Form and the Raw YAML/Markdown text editor be presented and synchronized on the editor panel?

**A:** Dual Tab Sync (Visual Schema Form & Raw YAML/Markdown Tabs): Provide two synchronized tabs on the editor panel ('Visual Form' adapted to the section schema, and 'Raw YAML/Text'). Editing either tab updates the other and reflects in the live preview in real time.

**Decision:** The editor panel will feature synchronized 'Visual Form' and 'Raw YAML/Text' tabs. Edits made in either tab instantly bi-directionally sync with the other and update the live preview pane seamlessly.

## Q3: Schema Form Generation Strategy

**Q:** How should the visual form dynamically adapt its controls for each section type's schema?

**A:** Dedicated Specialized Form Controls per Section Type + Universal Dynamic Fallback: Build tailored UI form controls for major section types (e.g. Quiz question list, Concept Map node/edge manager, Sandbox scenario builder, Flashcard list) alongside a dynamic schema fallback for nested object/array structures.

**Decision:** Form generation will combine specialized UI components tailored to core OKF section types (Quiz, Concept Map, Sandboxes, Flowcharts, etc.) with a recursive dynamic fallback form generator for arbitrary or nested schema structures.

## Q4: Saving & Persistence Strategy

**Q:** How should section edits be saved or persisted back to the codebase / file system?

**A:** Direct Disk Persistence (Dev Server API Endpoint) + Export/Download Fallback: In development mode (Vite dev server), add a lightweight API endpoint to save edits directly to the public/okf files on disk. Also provide 'Download YAML/Markdown' buttons for export.

**Decision:** Edits will be directly saved to disk under `public/okf/` via a Vite dev server endpoint (`/api/okf/save-section`) during local development, while also offering 'Download/Export' buttons for standalone deployment modes.

## Q5: Live Validation & Error Handling

**Q:** How should YAML syntax errors and schema validation issues be handled during real-time typing?

**A:** Non-blocking Inline Error Banner + Last-Good-State Preview: Show live validation errors (YAML syntax or schema mismatch) in a warning bar on the editor tab, while keeping the last valid section state rendered in the Live Preview pane to avoid breaking the view.

**Decision:** Errors in raw YAML or schema validation will be surfaced via non-blocking inline warning bars in the editor tab, while the Live Preview retains the last valid data state to ensure smooth uninterrupted authoring.
